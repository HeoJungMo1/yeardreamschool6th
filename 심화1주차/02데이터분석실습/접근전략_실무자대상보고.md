# 실무자 대상 혼잡도 개선 제안 — 접근 전략

- 작성일: 2026-06-25
- 타깃: 서울교통공사·지자체 교통정책 부서 실무자 / 철도운영 담당 / 안전관리자

---

## 1. 왜 접근 방식이 달라야 하는가

학술 보고서·일반 발표와 달리, 실무자는 다음 세 가지 기준으로 제안을 판단합니다.

| 질문 | 실무자 관점 |
|---|---|
| "이게 맞나?" | 내부 데이터와 현장 경험으로 즉시 검증 |
| "실행 가능한가?" | 예산·인력·법령·운행 다이어 제약 안에서 가능한가 |
| "우리 책임 범위인가?" | 기관 간 협의 필요 여부, 보고 라인 문제 |

→ **데이터 정확도 + 실행 가능성 + 책임 범위** 세 가지를 동시에 건드려야 설득 가능합니다.

## 2. 청중별 핵심 관심사 매핑

### A. 서울교통공사 운영 담당 실무자

- 관심: 열차 배차 다이어, 운행 횟수 증회 가능성, 회차 구간 여유, 예비열차 보유 수
- 통하는 언어: "배차 간격(시격)", "회차역", "단축 열차", "예비편성 투입"
- 주의: "증회하면 된다"는 주장에는 "운전 시격 최소값·회차 위치 제약"이 반박으로 옵니다.
- **대응 포인트**: TOP 3 혼잡 구간에 집중해 "회차 가능 역 기준 부분 증회" 안을 제시. 전 구간 증회가 아님을 명확히.

### B. 지자체 교통정책 부서 (서울시 도시교통실 등)

- 관심: 시민 민원 감소, 정책 성과 가시성, 타 교통수단(버스·자전거) 연계, 예산 당위성
- 통하는 언어: "수요 분산", "교통 형평성", "시차 출퇴근 제도화", "인센티브"
- 주의: 서울교통공사와 서울시는 별도 기관 — 운행 증회는 공사 소관, 시차 출퇴근·기업 캠페인은 시 소관.
- **대응 포인트**: 정책 유형별로 "공사 할 일 / 시가 할 일"을 구분한 슬라이드 1장이 효과적.

### C. 철도운영 담당 (기관사·역무·운전사령)

- 관심: 현장 안전, 무리한 탑승 통제 현실성, 안전요원 배치 실효성
- 통하는 언어: "승강장 안전문(PSD) 작동 지연", "탑승 거부 기준", "혼잡 칸 가이드 방송"
- 주의: "안전요원 배치"는 인건비·계약 문제로 즉각 반박 받음.
- **대응 포인트**: 기존 시스템(전광판·방송·앱 알림)을 활용한 **비용 0원 즉시 조치**를 선 제안, 이후 추가 인력 논의 순서로.

### D. 안전관리자 (안전본부·소방·비상대응팀)

- 관심: 혼잡도 150% 초과 시 압사 사고 위험, 대피 시간, 비상 게이트 용량
- 통하는 언어: "정원 대비 탑승률", "비상 대피 기준", "혼잡 모니터링 실시간화"
- 주의: "위험하다"는 주장만으로는 부족. 수치 기준을 제시해야 함.
- **대응 포인트**: 혼잡도 100% 초과 구간 리스트 + "현재 모니터링이 없다"는 공백을 지적 → 실시간 대시보드 필요성 제기.

## 3. 보고서·발표 구성 원칙

### 원칙 1 — 데이터 출처를 먼저 밝혀라

실무자는 "어디 데이터?"를 첫 번째로 묻습니다.

```
✅ "서울교통공사 제공 혼잡도정보(2026-03-31), 서울 열린데이터광장 카드 승하차(2026-05)"
❌ "최신 데이터 분석 결과"
```

### 원칙 2 — 제안은 "실행 주체 + 기간 + 비용 규모"로 표현해라

```
✅ "배차 간격 축소: 서울교통공사 운영 담당 / 단기 3개월 내 / 예비편성 재배치로 추가 비용 최소화"
❌ "열차 증회를 검토해야 한다"
```

### 원칙 3 — 한계를 먼저 인정해라

실무자는 현장 데이터가 훨씬 많습니다. "우리 분석의 한계"를 먼저 제시하면 신뢰가 올라갑니다.

```
✅ "열차 편성 수·운전 시격 데이터 없이 증회 규모는 제안 불가. 실제 가능 여부는 운영팀 확인 필요"
❌ "증회하면 혼잡도 XX% 감소 예상"
```

### 원칙 4 — 슬라이드보다 1페이지 요약이 먼저

실무자 미팅에서 긴 발표보다 **A4 1장 요약** (문제 → 데이터 근거 → 제안 3가지 → 요청 사항) 이 훨씬 효과적입니다.

## 4. 제안서 구조 (실무자 버전)

```
[표지]
서울 지하철 피크 혼잡 구간 개선안
— 데이터 기반 우선순위 제안
날짜 / 팀명

[1장] 문제 정의 (1슬라이드)
- 2026-05 기준 피크시간 이용량
- 혼잡도 100% 초과 구간 현황 지도

[2장] 데이터 근거 (2슬라이드)
- 출처·기간·행수 명시
- 핵심 수치 3개만 (혼잡도 최고값, 피크 이용량, 문제 구간 수)

[3장] 개선 대상 TOP 3 (3슬라이드, 각 1장)
- 구간·방향·시간대·혼잡도 수치
- 제안 처방 (운영측 조치 / 정책측 조치 구분)
- 예상 효과 (가능하면 타 사례 근거 포함)

[4장] 실행 로드맵 (1슬라이드)
- 즉시 / 단기 / 중기로 구분
- 담당 주체 명시 (공사 / 서울시 / 기업 협력)

[5장] 우리가 요청하는 것 (1슬라이드)
- "추가 데이터 공유 요청": 열차 편성 수, 운전 시격, 회차역 정보
- "파일럿 구간 협의": TOP 1 구간(사당 외선)만 먼저 실험
- "피드백 요청": 현장에서 이미 시도한 조치가 있는지 확인
```

## 5. 실무자 반박 예상 Q&A

| 예상 반박 | 준비된 답변 |
|---|---|
| "데이터가 오래됐다/부정확하다" | "공개 데이터 한계 인정. 내부 실측 데이터와 비교·보완 요청" |
| "증회는 운행 다이어 때문에 불가능하다" | "전 구간 증회 아닌 피크 30분 특정 구간 단축 열차 투입 안으로 재제안" |
| "안전요원 배치는 예산이 없다" | "즉시 조치는 방송·전광판 활용이며, 안전요원은 중기 검토로 분리 제안" |
| "이미 다 알고 있는 내용이다" | "그렇다면 현재 어떤 조치가 진행 중인지 확인 후, 미진한 부분만 보완 제안하겠다" |
| "우리 관할이 아니다" | "담당 부서가 어디인지 안내 요청 — 제안 방향을 조정해 재접촉" |

## 6. 설득력을 높이는 보조 자료

1. **타 도시 사례**: 도쿄 메트로 혼잡도 앱 실시간 공개, 런던 TfL 피크 시차 캠페인 효과 수치
2. **이태원 참사 이후 정책**: 밀집 위험도 기준 강화 — 혼잡도 150% 초과 구간을 안전 리스크로 프레이밍
3. **비용 대비 효과**: "전광판 방송 변경"은 추가 비용 0, 일 1회 안내만으로 칸별 분산 5~10% 가능 (타 사례 인용)

## 7. 접근 채널 (현실적 경로)

| 경로 | 현실성 | 방법 |
|---|---|---|
| 서울교통공사 열린 채용/공모전 연계 | ★★★ | 공사 연구·혁신 공모에 분석 보고서 제출 |
| 서울시 교통 빅데이터 챌린지 | ★★★ | 서울 열린데이터광장 연계 공모전 제출 |
| 학교 산학협력 채널 | ★★ | 지도교수 통해 공사 담당자 연결 |
| 직접 민원·제안 접수 | ★ | 서울교통공사 고객센터 정책 제안 접수 |

> **현실 조언**: 팀 프로젝트 발표가 목적이라면 "실무자에게 제안한다면 이렇게 할 것"이라는 **시뮬레이션 프레임**으로 발표하는 것이 가장 효과적입니다. 실제 접촉보다 "우리가 그들의 언어로 생각했다"는 것 자체가 발표 차별점이 됩니다.
